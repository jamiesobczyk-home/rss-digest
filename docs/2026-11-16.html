It's always DNS, so why are we running our own?

S2 needed to support unlimited basins for customers but hit a wall with AWS Route53's API rate limit of 5 UPSERTs per second, which couldn't handle their requirement for instantly-available DNS records. After confirming that other managed providers (GCP, Cloudflare, Azure) had similar limitations, the company decided to build its own authoritative DNS server. They implemented it in Go using the miekg/dns library to query their Cloud Spanner database in real-time, eliminating the rate limit bottleneck.

“…and the proof is checked in Lean”

A post from the Xena mathematics project explains how to interpret claims that theorems are "correct because checked in Lean," noting that while Lean verification is meaningful, AI-generated code requires systematic testing before such claims hold. OpenAI's recent theorem dump included 722 papers with ~45% containing Lean code, yet some non-Leanified papers have already been retracted for errors, highlighting that compilation alone doesn't guarantee correctness. The post outlines four critical questions to validate Lean repositories, beginning with whether the formal Lean statement actually matches the informal theorem statement—a distinction the author illustrates by showing how a misstated version of Fermat's Last Theorem can compile successfully.
