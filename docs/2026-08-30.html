Arbitrary code execution in QubesOS via copy-to-VM error reporting backchannel

QubesOS Security Bulletin 118 discloses an arbitrary code execution vulnerability in qvm-copy-to-vm where a compromised qube can inject malicious commands into dom0 during file copy operations. The vulnerability stems from incomplete filename sanitization in error reporting—the code removes only non-ASCII characters and quotes but leaves shell meta-characters intact before passing them to system(). An attacker with access to a compromised qube can exploit this when a user copies files from dom0 to inject arbitrary commands and seize control of QubesOS.
