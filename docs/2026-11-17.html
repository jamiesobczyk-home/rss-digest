California takes OpenAI to court

Prove It: Does a Learned Rule Actually Change What Your AI Assistant Writes? – Security Loop Series, Part 4

An experiment tested whether security rules learned from real code actually change AI assistant behavior by running 72 coding tasks across three scenarios: no rules, standard CodeGuard rules, and CodeGuard plus Foundry-learned rules. The learned rules reduced insecure trust check failures from 8 of 8 attempts to 0 or 1 of 4, while generic rules made no measurable difference. The study emphasizes the importance of verifying that security guardrails are actually being used before measuring their effectiveness.

How the Claude Code team thinks about verification

The Claude Code team, which generates ~90% of its code with Claude, uses verification loops to enable parallel agent work and improve quality by up to 10 points on structured tasks. The team prioritizes end-to-end tests that verify real user flows with definitive results over faster but less reliable unit tests, and property tests that catch edge cases agents typically miss. These verification mechanisms let agents check their own work with evidence, closing the loop to prevent recurring issues.

Buying a used phone? Make sure to check the IMEI first

When buying a used phone, request the seller's IMEI number—a unique 15-digit identifier that reveals whether the device is stolen or blacklisted and determines network compatibility. Find the IMEI via packaging, receipts, phone settings, or by dialing *#06#, then verify it using online checking services. Sellers who refuse to provide the IMEI may be selling stolen goods.
